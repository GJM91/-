# V-World 도시계획 규제 추출 (QGIS)

QGIS Python 콘솔에서 실행하여, 구역계(대상지) 기준으로 V-World OPEN API
데이터를 내려받아 도시계획 검토용 레이어를 만드는 스크립트입니다.

## 파일
- `03_vworld_urban_planning.py` — 실무용 추출 스크립트

## 하는 일
1. **두 개의 분석 범위** 생성
   - ① 구역계 (대상지 그 자체)
   - ② 구역계 + 2km : 경계에서 바깥으로 2km 오프셋한 "더 큰 사각형" (전체 맥락)
2. **V-World OPEN API 로 항상 전체 데이터** 수집
   - 용도지역·용도지구·용도구역·도시계획시설 등 각종 규제사항
     (국토관리 지역개발 > 용도지역지구)
   - 연속지적도_전국 (국토관리 지역개발 > 토지 > 연속지적도_전국, `LP_PA_CBND_BUBUN`)
3. **토지임야정보 조인 (PNU 기준)** — 실행 중 방식 선택
   - **① V-World API 자동조회 (권장, 파일 불필요)**
     - 국토관리 지역개발 계열 국가중점데이터API > 부동산 개방데이터 >
       토지임야정보 (`ladfrlList`) 를 조회하여 속성 부착
     - **2km 포함 전체 필지**에 조인합니다(대상 축소 없음). 효율을 위해
       ①법정동코드 단위 묶음 조회 → ②남은 필지 PNU 개별 조회(재시도) 2단계로 동작
     - `LADFRL_MAX_PNU` 는 "시간이 걸릴 수 있음" 안내 기준일 뿐 조회 범위를 줄이지 않음
   - **② CSV 파일에서 조인 (넓은 영역/대용량에 유리)**
     - 공공데이터포털(data.go.kr) 또는 V-World 에서 받은 CSV를 선택
     - 파일을 한 줄씩 스트리밍하며 지적도에 있는 PNU 행만 골라 읽음(메모리 절약)

> ℹ️ 지적도(연속지적도)와 토지임야정보 모두 V-World 오픈API로 조회 가능합니다.
> - **지적도** = V-World 2D 데이터 API (GeoJSON 벡터, PNU 포함)
> - **토지임야정보** = V-World NED API `ladfrlList` (PNU 단위) 또는 CSV 파일
4. 결과를 ① 구역계 / ② 구역계+2km 두 벌로 클립하여 레이어 그룹으로 정리
5. **파일 저장(Shapefile, EPSG:5186) + 스타일/라벨 자동 적용**
   - 실행 초반 **저장 폴더 팝업** → 각 레이어를 **ESRI Shapefile(.shp)** 로 저장
   - **저장 좌표계 = EPSG:5186** (Korea 2000 / 중부원점). 조회는 4326으로 받고
     저장 시 5186으로 투영합니다.
   - 저장 시 같은 이름의 **`.qml` 사이드카**(렌더러+라벨 포함)를 함께 만들어,
     그 SHP 를 나중에 열기만 해도 스타일·라벨이 자동 적용됩니다.
   - **스타일 폴더 팝업**(= `-1` 저장소의 `스타일 적용` 폴더) → 레이어별 QML 적용
     - 용도지역/용도지구/용도구역/도시계획시설 → `uname` 기준(5_1~5_4)
     - 연속지적도 → 지목·소유구분·공시지가 3종 SHP 사본(4_2/4_1/4_3)
     - 구역계 → 2_0 구역계 스타일
   - 두 팝업 모두 **취소 가능**(저장/스타일 생략)

   > SHP 는 필드명이 10자로 잘려 스타일 필드가 깨질 수 있어, **지적도는
   > 원본 지적도 필드 + 스타일 필드만** 담은 깔끔한 SHP 로 저장합니다.

### 라벨 표시
- **용도지역·용도지구**: `uname` 을 라벨로 표시
- **도시계획시설**: 기본은 `uname`, 단 **도로**는 아래 표기식으로 표시
  - `등급앞자(기능앞자)류-번호` 예) **중(주)1-26**
  - `grad_se` = 등급(광/대/중/소)+류, `pmi_nam` = 기능(주간선/보조간선/집산/국지)+번호
  - 표기식 상수 `ROAD_LABEL_EXPR` 에서 조정 가능

### 스타일 필드 매핑 (`styles/` 의 QML 은 아래로 수정되어 있음)
| 스타일 | 필드 |
|---|---|
| 지적도_지목 | `li_lndcgrC` (지목코드 1~28) |
| 지적도_소유구분 | `li_poses_1` (소유구분코드 0~9) |
| 지적도_공시지가 | `jiga` (숫자, ASCII) |
| 용도지역·지구·구역·도시계획시설 | `uname` |

## 사용법
1. 구역계(대상지) 폴리곤 레이어를 선택(활성)
2. `플러그인 > Python 콘솔 > 편집기`에서 이 파일을 열고 ▶ 실행
3. **저장 폴더** 선택 → **스타일 폴더**(`스타일 적용`) 선택
4. "토지임야정보 조인 방식" 팝업에서 방식 선택
5. 완료되면 저장 폴더(없으면 홈)에 `vworld_도시계획_결과.txt` 로그 저장

## 조정 포인트 (스크립트 상단 상수)
- `OFFSET_M = 2000` — 오프셋 거리(미터). 기본 2km
- `CLIP_WIDE_TO_RECT` — 광역 레이어를 사각형으로 자를지(True) / 걸친 필지 통째로 둘지(False)
- `REG_THEMES` — 조회할 규제 주제도 목록. 필요한 데이터ID를 추가 가능
- `PAGE_SIZE`, `MAX_PAGES` — 전체 데이터 페이징(끝까지 수집)
- `TILE_M` — 연속지적도 타일 한 변 길이(미터). 지적도가 여전히 덜 나오면 값을
  더 작게(예: 500), 요청이 너무 많으면 크게(예: 1000) 조정
- `MAX_TILES` — 타일 요청 수 상한(안전장치)

## 연속지적도(지적도) 관련 참고
연속지적도는 필지가 매우 조밀해서 넓은 영역을 한 번에 요청하면 V-World 가
오류/빈응답을 반환합니다. 그래서 이 스크립트는 분석 사각형을 `TILE_M` 크기의
작은 타일로 나눠 각각 조회한 뒤 PNU 기준으로 중복을 제거하여 **전체 필지**를
수집합니다. 진행 상황은 콘솔과 결과 txt 로그에 타일 단위로 기록됩니다.

## 참고
- `LP_PA_CBND_BUBUN`(연속지적도) 는 PNU 필드를 포함하며, CSV의 `고유번호`/`PNU`
  컬럼과 자동 매칭됩니다. CSV 인코딩(CP949/EUC-KR/UTF-8)과 구분자는 자동 감지합니다.
